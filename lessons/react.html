Why React & Core Mental Model

Discover what React is, why it became the world's most dominant front-end JavaScript library, how its declarative paradigm differs from traditional DOM manipulation, and how the Virtual DOM optimizes UI rendering.

What You Will Learn

01. What is React?

React is a free, open-source JavaScript library developed by Facebook (Meta) in 2013 for building rich, interactive user interfaces. Unlike heavyweight monolithic frameworks, React focuses primarily on the View layer of an application, making it lightweight, flexible, and capable of integrating with any backend or ecosystem.

Before React, web applications relied heavily on direct DOM manipulation using Vanilla JavaScript or jQuery:

imperative-vanilla.js 
// The Old Imperative Way: You tell the browser step-by-step HOW to update
const btn = document.getElementById('submit-btn');
const status = document.getElementById('status-msg');

btn.addEventListener('click', () => {
    btn.disabled = true;
    status.innerText = 'Sending request...';
    status.className = 'loading';
    fetchData().then(() => {
        btn.disabled = false;
        status.innerText = 'Success!';
        status.className = 'success';
    });
});

As applications grew in complexity with dozens of widgets, buttons, notifications, and forms, manually updating every element, managing edge cases, and keeping the UI in sync with backend data became a breeding ground for synchronization bugs (spaghetti code).

02. The Declarative Paradigm

React revolutionised front-end development by introducing the declarative mental model: you declare WHAT the user interface should look like for a given state, and React handles HOW to update the browser DOM automatically.

Core Mental Formula

In React, your user interface is purely a function of state:

UI = f(State)

Whenever your state changes, React runs the function again and updates the screen. You never have to manually query or modify DOM nodes.

03. Component-Based Architecture

React structures entire applications as a tree of independent, self-contained, and reusable building blocks called Components. Each component encapsulates its own HTML markup, styling logic, and internal state.

Reusability

Build a component once (e.g. Button, Card, Navbar) and reuse it across multiple screens with different props.

Maintainability

Isolate bugs to a specific component without worrying about unintended side effects across unrelated UI sections.

Composability

Combine small, focused components together like LEGO bricks to assemble massive, feature-rich web platforms.

04. The Virtual DOM & Reconciliation

Directly mutating the browser's Real DOM is computationally expensive. Whenever a DOM element changes, the browser must recalculate page geometry, recompute CSS styles, and perform layout repaints.

React solves this performance bottleneck using an in-memory representation called the Virtual DOM:

  1. Virtual DOM Snapshot: When a component's state changes, React creates an in-memory Virtual DOM tree representing the new UI.
  2. Diffing (Reconciliation): React compares the new Virtual DOM tree with the previous Virtual DOM snapshot using a fast diffing algorithm.
  3. Batch Patching: React computes the minimal set of changes necessary and updates only those specific nodes in the real browser DOM in a single optimized batch.

Why does React use an in-memory Virtual DOM instead of updating the real DOM directly?

  1. Because modern browsers do not support direct HTML manipulation.
  2. To compare previous and new states (diffing) and batch minimal updates, avoiding expensive browser repaints.
  3. To convert JavaScript code directly into binary web assembly instructions.

Updating the real browser DOM triggers costly layout calculations and repaints. React's Virtual DOM diffs changes in memory first and applies only the exact surgical changes required.

01. Why Vite?

For years, beginners started with Create React App (CRA). However, CRA is now deprecated by the React team because its Webpack bundler rebuilt the entire application bundle on every code change, causing slow startup times and sluggish reloads in medium-to-large projects.

Vite (French for "quick", pronounced /veet/) leverages native ES modules (ESM) supported by modern browsers and the ultra-fast Go-based compiler esbuild. Vite provides instant server start, lightning-fast Hot Module Replacement (HMR), and optimized production rollups.

04. The Mounting Process: index.html to main.jsx

How does React take over the web page? It starts in index.html with a single container div:

index.html 
<!doctype html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <title>My React App</title>
  </head>
  <body>
    <!-- React will mount inside this empty container -->
    <div id="root"></div>

    <!-- Entry script that boots React -->
    <script type="module" src="/src/main.jsx"></script>
  </body>
</html>

Next, src/main.jsx grabs that #root element using ReactDOM.createRoot() and renders the top-level <App /> component inside it:

src/main.jsx 
import React from 'react';
import ReactDOM from 'react-dom/client';
import App from './App.jsx';
import './index.css';

ReactDOM.createRoot(document.getElementById('root')).render(
  <React.StrictMode>
    <App />
  </React.StrictMode>
);
What is React.StrictMode?

<React.StrictMode> is a development-only helper tool that highlights potential bugs, deprecated APIs, and accidental side effects by intentionally executing components twice in local dev. It has zero performance impact on production builds.

Where does the primary React application mount into the browser HTML?

  1. Directly inside the <head> tag of index.html
  2. Inside the package.json manifest script
  3. Inside <div id="root"></div> via ReactDOM.createRoot() in main.jsx

ReactDOM.createRoot selects the HTML element with id root and renders the top-level <App /> tree inside it.

01. What is JSX?

JSX stands for JavaScript XML. It is a syntax extension for JavaScript that allows you to write markup that looks almost identical to HTML directly inside your JS/JSX files.

Browsers cannot understand JSX directly. During your build process, Vite uses Babel or SWC to convert every JSX element into pure JavaScript function calls:

What you write (JSX) vs What the browser executes 
// 1. What you write in JSX:
const element = <h1 className="title">Hello React!</h1>;

// 2. What it transpiles to behind the scenes:
const element = React.createElement(
  'h1',
  { className: 'title' },
  'Hello React!'
);

02. Embedding Dynamic JavaScript Expressions

In standard HTML, you write static text. In JSX, you can embed ANY valid JavaScript expression by wrapping it in curly braces {}:

expressions.jsx 
function UserProfile() {
  const user = {
    name: 'Sophia Chen',
    role: 'Full-Stack Engineer',
    avatar: 'https://images.unsplash.com/photo-1494790108377-be9c29b29330',
    reputation: 98.4
  };

  const getGreeting = () => 'Welcome back';

  return (
    <div className="profile-card">
      <img src={user.avatar} alt={user.name} width="64" height="64" />
      <h2>{getGreeting()}, {user.name}!</h2>
      <p>Role: <strong>{user.role.toUpperCase()}</strong></p>
      <p>Score: {user.reputation * 10} / 1000</p>
      <p>Next review: {2026 + 1}</p>
    </div>
  );
}

03. Crucial Rules & Differences from HTML

HTML Standard JSX Equivalent Reason
class="card" className="card" class is a reserved keyword in JavaScript for defining classes.
for="email" htmlFor="email" for is a reserved keyword in JavaScript for loops.
onclick="handleClick()" onClick={handleClick} JSX attributes use camelCase and pass function references, not string scripts.
style="color: red; font-size: 16px" style={{ color: 'red', fontSize: '16px' }} Inline styles in JSX must be JavaScript objects with camelCase CSS properties.
Unclosed tags: <img>, <input>, <br> Self-closing: <img />, <input />, <br /> JSX follows strict XML syntax rules. Every single opened tag must be closed.

04. The Single Parent Rule & React Fragments

A React component can only return a single root element. If you try to return two sibling tags side-by-side, transpilation will fail with a syntax error:

invalid-vs-valid.jsx 
// ❌ SYNTAX ERROR: Adjacent JSX elements must be wrapped in an enclosing tag
return (
  <h1>Header</h1>
  <p>Description</p>
);

// ✅ SOLUTION: Wrap in a React Fragment (<>...</>) without adding useless divs to the DOM!
return (
  <>
    <h1>Header</h1>
    <p>Description</p>
  </>
);

Which attribute name must you use in JSX when adding CSS classes to an element?

  1. className
  2. class
  3. cssClass
  4. classList

Because class is already a reserved keyword in JavaScript for defining ES6 classes, React uses className to assign HTML class names.

01. Functional Components in Modern React

In modern React, a Component is simply a JavaScript function that accepts input (props) and returns user interface markup (JSX). In the past, developers wrote Class components with render() methods, but since React 16.8 (Hooks), functional components are the official industry standard.

Header.jsx 
// Modern Functional Component
export default function Header() {
  return (
    <header className="site-header">
      <div className="logo">CodeTutorium</div>
      <nav>
        <a href="#features">Features</a>
        <a href="#pricing">Pricing</a>
      </nav>
    </header>
  );
}
Critical Rule: Uppercase Naming

React component names MUST start with a capital letter (e.g. Header, UserProfile, ProductCard). If you start a component with a lowercase letter (e.g. function header()), React treats it as an ordinary HTML tag (like <div> or <header>) and will not render your component!

02. Component Composition

Instead of cramming hundreds of lines of HTML into a single monolithic App.jsx, senior developers split interfaces into modular components and compose them together:

App.jsx 
import Header from './components/Header';
import HeroSection from './components/HeroSection';
import FeatureList from './components/FeatureList';
import Footer from './components/Footer';

export default function App() {
  return (
    <div className="app-shell">
      <Header />
      <main>
        <HeroSection />
        <FeatureList />
      </main>
      <Footer />
    </div>
  );
}

03. Pure Functions: Keeping Components Idempotent

React relies heavily on the mathematical concept of Pure Functions. A pure function has two characteristics:

  • It minds its own business: It does not mutate any variables or objects that existed before the function call.
  • Same inputs, same outputs: Given the same inputs, it will always return the exact same JSX result.
purity-rules.jsx 
// ❌ IMPURE: Mutating external variables during render causes random bugs
let visitorCount = 0;
function BadCounter() {
  visitorCount = visitorCount + 1; // Modifies external state during render!
  return <p>Visitor: {visitorCount}</p>;
}

// ✅ PURE: Keeps rendering logic isolated and predictable
function GoodCounter({ currentCount }) {
  return <p>Visitor: {currentCount}</p>;
}

03. Props are Read-Only (Immutable!)

Golden Rule: Never Mutate Props!

Props in React are strictly read-only. A child component must never modify the props passed to it:

function BadComponent(props) {
  props.title = "New Title"; // ❌ RUNTIME ERROR! Props are frozen/immutable!
}

If a component needs to change data over time in response to user action, that data belongs in State, not props!

04. The Versatile children Prop

Sometimes you want a component to act as a visual container or wrapper (like a Modal dialog, Card, or Layout container) without knowing ahead of time what elements will go inside it. React provides the special children prop for this exact slot pattern:

      </div>
      <div className="card-body">
        {/* Anything nested between <Card>...</Card> renders here! */}

01. Why Variables Don't Work for Interactive UIs

Suppose you want a simple counter button that increments when clicked. If you try using a regular local variable:

broken-counter.jsx 
export default function BrokenCounter() {
  let count = 0;

  function handleClick() {
    count = count + 1;
    console.log('Current count:', count); // Logs 1, 2, 3 in the console...
  }

  // ❌ The screen NEVER updates! It stays stuck at 0!
  return <button onClick={handleClick}>Clicked {count} times</button>;
}

Why did this fail? Two critical reasons:

  1. Local variables don't persist across renders: Whenever React re-executes a component function, local variables are reinitialized from scratch.
  2. Changing local variables does not notify React: React has no magical listener watching local variables. To trigger a re-render, you must inform React through its official state API.

02. Enter the useState Hook

React provides the useState Hook to store data that persists across renders and triggers an automated UI update when changed:

WorkingCounter.jsx 
import { useState } from 'react';

export default function WorkingCounter() {
  // Syntax: const [stateValue, setterFunction] = useState(initialValue);
  const [count, setCount] = useState(0);

  function handleIncrement() {
    setCount(count + 1); // Updates state and schedules a re-render!
  }

  return (
    <div className="counter-box">
      <h2>Score: {count}</h2>
      <button onClick={handleIncrement}>Add +1</button>
      <button onClick={() => setCount(0)}>Reset</button>
    </div>
  );
}

03. The Functional Updater Pattern

React batches multiple state updates together for performance. If you need to calculate the next state based on the previous state, always pass an updater callback function rather than relying on the raw state variable:

stale-vs-functional.jsx 
// ❌ BUGGY: If called 3 times in a row, it only increments once!
function incrementThreeTimesBroken() {
  setCount(count + 1);
  setCount(count + 1);
  setCount(count + 1);
}

// ✅ SAFE & PROFESSIONAL: Uses previous state snapshot guarantee
function incrementThreeTimesSafe() {
  setCount(prev => prev + 1);
  setCount(prev => prev + 1);
  setCount(prev => prev + 1); // Correctly increments by +3!
}

04. Updating Objects & Arrays in State

Remember: React detects changes by comparing object memory references (shallow equality). If you mutate an existing array or object directly in place, its memory reference stays identical, and React will skip re-rendering!

immutability-recipes.jsx 
const [user, setUser] = useState({ name: 'Alex', age: 25, city: 'London' });
const [items, setItems] = useState(['React', 'Vite']);

// 1. Updating an Object (Spread existing properties, overwrite target):
setUser(prev => ({
  ...prev,
  city: 'Tokyo'
}));

// 2. Adding to an Array (DO NOT use items.push!):
setItems(prev => [...prev, 'TypeScript']);

// 3. Removing an item from an Array (use .filter()):
setItems(prev => prev.filter(item => item !== 'Vite'));

How should you add a new item to an array stored in React state?

  1. items.push(newItem)
  2. items[items.length] = newItem
  3. setItems(prev => [...prev, newItem])

Direct mutation via .push() does not create a new array reference, meaning React will not detect the change. Spreading into a new array ensures state immutability.

Handling Events & Synthetic Events

01. React SyntheticEvents

When you attach an event handler in React (like onClick or onKeyDown), React does not attach raw event listeners directly to the individual DOM nodes. Instead, it wraps native browser events in an object called a SyntheticEvent.

The SyntheticEvent provides a completely identical interface across all browsers (Chrome, Safari, Firefox, Edge, mobile browsers), eliminating cross-browser inconsistencies with event properties.

02. Passing Functions: Reference vs Immediate Invocation

The #1 Beginner Trap: Immediate Invocation

You must always pass a function reference to an event attribute, NOT the result of calling the function immediately:

// ❌ WRONG: Calls handleClick() immediately during rendering!
// This triggers an infinite re-render loop if handleClick calls setState!
<button onClick={handleClick()}>Click Me</button>

// ✅ CORRECT: Passes the function as a reference to be called upon user click
<button onClick={handleClick}>Click Me</button>

// ✅ CORRECT: Using an inline arrow function when you need to pass custom arguments
<button onClick={() => handleDelete(product.id)}>Delete Product</button>

03. Common Event Handlers in Practice

    setText(e.target.value);
  }

  // Key Down Event (e.g. detecting Enter key)
  function handleKeyDown(e) {
    if (e.key === 'Enter') {
      alert(`Submitted: ${text}`);
    }
  }

02. Why React Demands the key Prop

Notice the key={dev.id} attribute on the <li> element above. If you omit it, React will print a red warning in your browser console: "Each child in a list should have a unique 'key' prop."

Why is this key so critical? During reconciliation, when an item is added, moved, sorted, or removed from a list, React compares the new list with the previous list. Without a stable key, React cannot tell which exact item was modified versus which items just shifted position.

03. The Danger of Using Array Index as a Key

Why Index as Key Causes Data Corruption

Beginners often write items.map((item, index) => <li key={index}>...</li>). This is dangerous if your list is dynamic!

If you delete the first item at index 0, the second item now becomes index 0, the third becomes index 1, and so on. Any internal input values, checkbox checks, or animations attached to index 0 will now mistakenly stay bound to the wrong item!

Rule: Always use unique, persistent IDs (e.g. database UUIDs, item.id, or crypto.randomUUID() when creating items).

01. What is a Side Effect?

A pure React component should only receive props and return JSX. However, real-world applications need to interact with the outside world beyond React's rendering pipeline. These operations are called Side Effects:

  • Fetching data from an external REST API
  • Setting timers (setInterval, setTimeout)
  • Directly changing the document title (document.title = '...')
  • Listening to global window events (window resize, scroll)
  • Reading or writing to browser localStorage

02. The 3 Dependency Array Modes

The useEffect hook takes two arguments: an effect callback function, and an optional Dependency Array. How and when it executes depends entirely on this array:

useEffectModes.jsx 
import { useEffect, useState } from 'react';

// Case 1: No Dependency Array (DANGEROUS: Runs after EVERY single render!)
useEffect(() => {
  console.log('Runs after initial mount AND every state/prop update!');
});

// Case 2: Empty Dependency Array [] (Runs ONCE on initial Mount only)
useEffect(() => {
  console.log('Runs exactly ONCE when the component first appears on screen.');
}, []);

// Case 3: With Dependencies [userId] (Runs on Mount + whenever userId changes)
useEffect(() => {
  console.log(`Fetching new data because userId changed to: ${userId}`);
}, [userId]);

03. The Cleanup Function

If your effect creates an ongoing background process (like a recurring setInterval or a window addEventListener), it will continue running in memory even after the user navigates away from that page, causing severe performance memory leaks!

To prevent this, return a cleanup function from your effect:

WindowResizeListener.jsx 
import { useState, useEffect } from 'react';

export default function WindowWidthTracker() {
  const [windowWidth, setWindowWidth] = useState(window.innerWidth);

  useEffect(() => {
    function handleResize() {
      setWindowWidth(window.innerWidth);
    }

    // 1. Set up the event listener on Mount
    window.addEventListener('resize', handleResize);
    console.log('Resize listener attached.');

    // 2. Return cleanup function (Runs on Unmount or before re-running effect)
    return () => {
      window.removeEventListener('resize', handleResize);
      console.log('Listener cleaned up! No memory leaks.');
    };
  }, []); // Empty array ensures listener is only attached once

  return <p>Current Screen Width: <strong>{windowWidth}px</strong></p>;
}

When does the cleanup function returned from a useEffect execute?

  1. Only when the browser window closes.
  2. When the component unmounts, and immediately before re-running the effect on dependency change.
  3. Before the component renders for the first time.

The cleanup function runs when the component is unmounted from the DOM and before the effect runs again due to dependency updates, cleaning up lingering subscriptions or timers.

          signal: controller.signal

          setError(err.message);

  if (isLoading) return <div className="loading-spinner">Fetching developers...</div>;

  const [isRunning, setIsRunning] = useState(false);

  const timerIdRef = useRef(null);

    if (isRunning) return;
    setIsRunning(true);
    timerIdRef.current = setInterval(() => {
      setSeconds(prev => prev + 1);
    }, 1000);
  }

  function handleStop() {
    clearInterval(timerIdRef.current);
    timerIdRef.current = null;
    setIsRunning(false);
  }

    handleStop();
    setSeconds(0);
  }

  return (
    <div className="stopwatch-box">
      <h1>{seconds}s</h1>
      <button onClick={handleStart} disabled={isRunning}>Start</button>
      <button onClick={handleStop} disabled={!isRunning}>Pause</button>
      <button onClick={handleReset}>Reset</button>
    </div>
  );
}

  1. The component immediately re-renders with the new value.
  2. The value changes silently in memory without triggering a re-render.
  3. React throws an error because refs are read-only.

01. What is a Custom Hook?

A custom hook is simply a regular JavaScript function whose name starts with "use" (like useLocalStorage, useAuth, or useWindowSize) and that calls other React hooks (like useState, useEffect, useRef) inside itself.

The Two Golden Rules of Hooks
  1. Only call Hooks at the top level: Never call hooks inside loops, conditional if statements, or nested functions. React relies on the exact execution order of hooks across renders.
  2. Only call Hooks from React functions: Only call hooks from React functional components or other custom hooks. Never call them from ordinary helper scripts.

02. Building useLocalStorage

Have you ever wanted state to automatically persist in localStorage so it survives page reloads? Let's build a custom hook that behaves just like useState, but syncs to browser storage:

src/hooks/useLocalStorage.js 
import { useState, useEffect } from 'react';

export function useLocalStorage(key, fallbackValue) {
  // Initialize state from localStorage or fallback
  const [value, setValue] = useState(() => {
    try {
      const saved = localStorage.getItem(key);
      return saved !== null ? JSON.parse(saved) : fallbackValue;
    } catch (e) {
      console.error('Failed to read localStorage:', e);
      return fallbackValue;
    }
  });

  // Automatically sync changes back into localStorage
  useEffect(() => {
    try {
      localStorage.setItem(key, JSON.stringify(value));
    } catch (e) {
      console.error('Failed to write localStorage:', e);
    }
  }, [key, value]);

  return [value, setValue];
}

03. Building useFetch

src/hooks/useFetch.js 
import { useState, useEffect } from 'react';

export function useFetch(url) {
  const [data, setData] = useState(null);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    let isMounted = true;
    setLoading(true);

    fetch(url)
      .then(res => {
        if (!res.ok) throw new Error(`HTTP Error ${res.status}`);
        return res.json();
      })
      .then(result => {
        if (isMounted) setData(result);
      })
      .catch(err => {
        if (isMounted) setError(err.message);
      })
      .finally(() => {
        if (isMounted) setLoading(false);
      });

    return () => { isMounted = false; };
  }, [url]);

  return { data, loading, error };
}

  3. The function must be decorated with @hook.

01. The Prop Drilling Problem

02. The Context API Solution

React's Context API allows you to "teleport" data directly to any component in the tree, regardless of depth:

01. Why and When Does React Re-render?

A React component re-renders under two primary circumstances:

  2. Its parent component re-renders: By default, whenever a parent component re-renders, ALL of its children re-render as well, even if their props have not changed!

  return total;

export default function ComputeBox() {

export default function TaskList() {
  const [tasks, setTasks] = useState([...]);

What is the difference between useMemo and useCallback?

  1. useMemo caches the calculated result of a function, while useCallback caches the function definition itself.
  2. useMemo is for asynchronous API calls, while useCallback is for synchronous math.
  3. They are identical aliases for the exact same function.

useMemo(() => fn(), [deps]) caches the returned value of a calculation. useCallback(fn, [deps]) caches the function instance itself across renders.

import { createContext, useContext, useState, useEffect } from 'react';

const CartContext = createContext();

export function CartProvider({ children }) {
  const [cart, setCart] = useState(() => {
    try {
      const saved = localStorage.getItem('cart_items');
      return saved ? JSON.parse(saved) : [];
    } catch (e) { return []; }
  });

  useEffect(() => {
    localStorage.setItem('cart_items', JSON.stringify(cart));
  }, [cart]);

  function addToCart(product) {
    setCart(prev => {
      const existing = prev.find(item => item.id === product.id);
      if (existing) {
        return prev.map(item => 
          item.id === product.id ? { ...item, quantity: item.quantity + 1 } : item
        );
      }
      return [...prev, { ...product, quantity: 1 }];
    });
  }

  function removeFromCart(productId) {
    setCart(prev => prev.filter(item => item.id !== productId));
  }

  function updateQuantity(productId, delta) {
    setCart(prev => prev.map(item => {
      if (item.id === productId) {
        const newQty = item.quantity + delta;
        return newQty > 0 ? { ...item, quantity: newQty } : item;
      }
      return item;
    }));
  }

  function clearCart() {
    setCart([]);
  }

  const cartCount = cart.reduce((sum, item) => sum + item.quantity, 0);
  const cartTotal = cart.reduce((sum, item) => sum + (item.price * item.quantity), 0);

  return (
    <CartContext.Provider value={{
      cart,
      addToCart,
      removeFromCart,
      updateQuantity,
      clearCart,
      cartCount,
      cartTotal
    }}>
      {children}
    </CartContext.Provider>
  );
}

export function useCart() {
  return useContext(CartContext);
}

  const [toast, setToast] = useState('');

  function handleAdd(product) {
    addToCart(product);
    setToast(`Added "${product.name}" to cart!`);
    setTimeout(() => setToast(''), 3000);
  }

  const filtered = PRODUCTS.filter(p => {
    const matchCat = category === 'All' || p.category === category;
    const matchSearch = p.name.toLowerCase().includes(search.toLowerCase());
    return matchCat && matchSearch;
  });

  return (
    <div className="catalog-view">
      {toast && <div className="toast-notification">✓ {toast}</div>}

      <div className="filter-bar">
        <input 
          type="search" 
          placeholder="Search gear..." 
          value={search} 
          onChange={e => setSearch(e.target.value)} 
        />
        <div className="pill-group">
          {['All', 'Audio', 'Peripherals', 'Displays', 'Accessories'].map(cat => (
            <button 
              key={cat} 
              className={category === cat ? 'pill active' : 'pill'} 
              onClick={() => setCategory(cat)}
            >
              {cat}
            </button>
          ))}
        </div>
      </div>

      <div className="product-grid">
        {filtered.map(product => (
          <div key={product.id} className="product-card">
            <div className="tag">{product.category}</div>
            <h3>{product.name}</h3>
            <div className="rating">★ {product.rating} / 5.0</div>
            <div className="card-footer">
              <span className="price">${product.price.toFixed(2)}</span>
              <button onClick={() => handleAdd(product)} className="btn-add">
                + Add to Cart
              </button>
            </div>
          </div>
        ))}
      </div>
    </div>
  );
}

        </div>

          {cart.length === 0 ? (
